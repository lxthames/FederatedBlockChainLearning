# Download and rebuild the SIFT routing case study

The original project's custom shard labels cannot be recovered from the public
nearest-neighbor benchmark. They stay unverified and are never overwritten.
The replacement is an explicitly named **SIFT1M routing case study**, not SIFT1B.

## Source and provenance

The official INRIA/TexMex archive is
`ftp://ftp.irisa.fr/local/texmex/corpus/sift.tar.gz`.
The FAISS benchmark instructions identify this source:
https://github.com/facebookresearch/faiss/blob/main/benchs/README.md

Its separate files contain database vectors (`sift_base.fvecs`), learning queries
(`sift_learn.fvecs`), held-out queries (`sift_query.fvecs`), and published test
ground truth (`sift_groundtruth.ivecs`). The downloadable archive is about 168 MB.
The source uses anonymous FTP; the job records its size, modification time and
SHA-256. A hash records the retrieved content, not a publisher signature.

## Background preparation

```powershell
.\.venv-trust\Scripts\python.exe -m scripts.data_preparation.sift --threads 4
```

The tool downloads with resume support, extracts only four regular files to fixed
paths, checks the vector record dimensions, and runs CPU FAISS `IndexFlatL2` exact
top-1000 searches for training and test queries. It cross-checks sampled results
and the published ground truth with independent exhaustive float64 distances.
Queries retain their original row ordering. The process can take hours and keeps
GPU computation available to the classification study.

Four- and eight-shard assignments are generated by deterministic centroid
partitioning, fitted only to database vectors with seed 2027. Each target is an
actual histogram of the query's exact nearest-neighbor IDs under those stored
assignments. Every row must sum to 1000. No labels are interpolated or sampled
from a probability distribution.

The separate output root is `data/sift1m-verified/`. It preserves the archive,
source vectors, exact neighbor IDs, shard assignments/centroids, normalized
training-query features, test queries, targets, checksums and a provenance JSON.
The existing loader requires a filename `SIFT1B_train.npy`; inside this new root
that filename is a compatibility alias for the SIFT1M **learning query** array.
The provenance JSON explicitly identifies the dataset and its actual row counts.
The paper must use those counts rather than infer scale from filenames.

Progress: `artifacts/sift-data-preparation/status.json`; logs and the launcher PID
are in the same directory. The proof-of-correspondence flag is written only after
the exactness, published-ground-truth and row-mass checks pass. A failed or partial
preparation does not certify any dataset. Existing verified outputs are immutable.

## Run the supporting case study after preparation succeeds

The author selected the new labels on October 19, 2026. The dedicated background
coordinator validates all recorded hashes, waits for preparation if necessary,
screens attacks on seeds 3/5/7, and then executes matched five-seed case-study
cells. It preserves configurations, source identity, dataset identity, errors,
held cells and complete five-seed analyses.

```powershell
.\.venv-trust\Scripts\python.exe -m scripts.data_preparation.run_sift_study --device cpu
```

CPU is selected to keep the classification GPU job available. Concurrent runtime
measurements are exploratory. Progress is in `artifacts/sift1m-study/status.json`.
The 180-cell main matrix includes four/eight clients, EMH-DNN/MLP,
FedAvg/FLTrust/two-layer, clean/sign-flip/gradual conditions, and five matched
evaluation seeds. Attacks that fail the development effectiveness gate are held
and cannot support robustness claims. Tiny federations quantize the nominal
30% poisoning fraction to one of four or two of eight clients; each run records
the actual fraction as 25% in its dataset identity sidecar.

The direct CLI alternative below executes the matrix without the coordinator's
development attack gate; use the coordinator for the staged paper study.

Use the existing SIFT case-study configs with the new data root and fresh output
directories, for example:

```powershell
.\.venv-trust\Scripts\python.exe -m scripts.research.cli run-manifest --manifest artifacts/trust-2027/manifests/sift_case_study.json --data-root data/sift1m-verified --output-root results/trust-2027/sift1m-case-study --resume
```

These are new experiments with regenerated labels. They must not be represented
as verification or reproduction of the original reported Recall@1000. Preserve
their separate dataset-root provenance alongside the run fingerprints.
